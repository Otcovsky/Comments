## Диагностика 1. Во что упирается ёмкость

Прогоны `2026-11-07_1209_baseline-v2/step` (50 подключений, вкладок нет) и `2026-11-07_1339_step-no-ws` (`WS_CLIENTS=0 bash perf/run.sh step step-no-ws`), код `1de796b`.

**CPU базы** (мониторинг Oracle, поминутно): на 20 итерациях/с в среднем 41–48%, пики 53–56%; на 24 итерациях/с пики 87–93%. Строк прочитано на 20% больше, а пики CPU выросли почти вдвое: на 24 итерациях/с запросы уже ждут друг друга в базе. CPU backend при этом 28%, так что упирается база, а не процесс приложения или его восемь потоков к базе.

**Без WebSocket ёмкость 64 итерации/с вместо 20.**

| | с подключениями, 20 it/s | с подключениями, 24 it/s | без подключений, 24 it/s | без подключений, 64 it/s |
|---|---|---|---|---|
| SLO | выполнен | нарушен | выполнен | выполнен |
| `create p95`, мс | 216 | 1102 | 26 | 42 |
| `list p95`, мс | 86 | 310 | 68 | 111 |
| SQL-запросов на запрос к API | 2,74 | 2,74 | 2,21 | 2,15 |
| строк прочитано на запрос к API | 15 789 | 16 041 | 11 327 | 11 578 |

Почти всё время записи — рассылка событий: после сохранения комментария сервер для каждой открытой сортировки считает позицию комментария (`queries.positions`, `COUNT` по корневым комментариям; для `username` и `email` — с соединением с авторами), а для ответа ещё и число ответов у родителя. Ответ на запрос ждёт рассылку. Открытые зоны в тесте — четыре сортировки из таблицы `VIEWS`.

**Оговорки.** Без подключений приложение не настоящее: тест меряет цену рассылки, а не допустимую конфигурацию. В базовом прогоне была открытая вкладка (около 15 запросов в минуту), в прогоне без подключений посторонних запросов нет; на разницу втрое это не влияет.

**Следующее узкое место без рассылки.** На 80 итерациях/с SLO нарушен двумя пропущенными итерациями, CPU backend 84%: один процесс Python приближается к одному ядру.

**Что из этого следует.** Сначала дешевле сделать подсчёт позиций: не ждать его в ответе на запрос, считать его одним запросом на все сортировки или не считать для сортировок, где новый комментарий заведомо не попадёт на открытые страницы. Затем — 11 тысяч строк на запрос, которые остаются и без рассылки: `count` всех корневых комментариев в каждом списке и сортировки по `username` и `email` без индекса.
